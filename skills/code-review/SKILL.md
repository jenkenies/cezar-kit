# 代码 Review

- 对当前 worktree 执行 `git diff` 全量审查,同时对照设计文档与 `ai-rules/` 规则
- 重点检查:
  - 模块分层依赖方向是否被破坏
  - 命名、枚举使用(遵守 `ai-rules/CommonEnumRule.md` 等)与既有风格一致性
  - 边界条件、空值处理、异常处理
  - 事务边界与并发安全
  - 日志规范、敏感信息硬编码(密钥/内网地址/手机号)
  - 是否偏离设计文档(超范围改动 = 问题)
- 发现问题:**直接修复**(你是本流程的质量把关人,不把问题清单留给下一环)
- 输出审查结论:改了什么 / 修复了哪些问题 / 有哪些需要人工知晓但未改的点
